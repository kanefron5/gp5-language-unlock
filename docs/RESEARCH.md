# GP-5 1.0.6: экспериментальная разблокировка языков

Дата: 2026-10-07. Патч проверен пользователем на одной китайской GP-5: запись завершилась, английский доступен и сохраняется после перезапуска; iOS Suite при подключении тоже остаётся на английском. Остальные выводы об активационном коде получены статическим анализом.

## Что входит

- `gp5_language_patch.py`: меняет одну инструкцию в точной официальной прошивке и пересчитывает CRC. Работает на macOS, Windows и Linux, Python 3.9+, без зависимостей. Устройство не подключает и не прошивает.
- `gp5_diag.py`: скрипт Claude 0.19 с обновлением до 0.20-block-crc. Проверяет также CRC каждого блока. Нативный протокол прошивки и обработка отказа версии сохранены.
- `evidence/`: дизассемблирование исследованных функций Android-приложения и прошивки.

## Входной файл

Поддерживается только распакованный официальный `GP-5_USB_V1.0.6_20250626.bin`:

- размер: 2094404 байта;
- SHA-256: `259ac4e77d3df792ff48e55feff52427ff2ea9ed63cb65785360a23a10dbaf42`;
- URL: https://valeton.oss-accelerate.aliyuncs.com/update/gp-5/pkg/GP-5_USB_V1.0.6_20250626.bin

Другие версии и другие модификации отклоняются. Входной и существующий выходной файлы не перезаписываются.

## Создание и проверка

Положить скрипты рядом с оригинальным `firmware.bin`, затем:

```sh
python3 gp5_language_patch.py patch firmware.bin -o firmware_languages.bin
python3 gp5_diag.py check firmware_languages.bin
python3 gp5_diag.py native-crc firmware_languages.bin
```

Последняя команда требует macOS, ARM64 Python и установленный проверенный Valeton Suite 2.1.0. На Linux при подготовке пакета нативная проверка не запускалась. Ожидается `checkCrc: return_code 0`.

Результат патчера должен иметь:

- SHA-256: `6373ccee45d5e8689d4d061700d138d2b6aabdbcfa317702876f9c36a2ce2bf2`;
- CRC файла: `0x423f`;
- CRC блока b: `0x04d2`;
- `crc_ok: true`, у диагностического скрипта также `block_crc_ok: true` и `valid: true`.

CRC отключать не требуется. Проверка принимает корректно пересчитанные суммы независимо от SHA-256 файла прошивки. Ограничения по SHA-256 нативной библиотеки Suite сохраняются.

## Экспериментальная прошивка

Команда, соответствующая успешной записи официальной 1.0.6 в предоставленном отчёте Claude, с новым выходным файлом:

```sh
python3 gp5_diag.py native-flash firmware_languages.bin --enter-update --announce-version V999 --version-reject-ok --trace-midi
```

Если педаль уже вручную включена в загрузчик:

```sh
python3 gp5_diag.py native-flash firmware_languages.bin --bootloader --suite-handshake --announce-version V999 --version-reject-ok --trace-midi
```

Здесь объявление `V999` меняет только команду 0x69. Версия в файле остаётся 1.0.6. Вторая команда явно включает `--suite-handshake`: один `--bootloader` в текущем коде не вызывает этот обмен.

Успех записи: итоговый нативный статус 0 и `flash_finished`. Затем нужно проверить загрузку педали, доступность English/Chinese, сохранение выбора после перезапуска и язык мобильного приложения при повторном подключении.

Патч меняет исполняемый код. Статические проверки не гарантируют загрузку и работу педали. Наличие работоспособного оригинального файла даёт путь к повторной официальной записи, но восстановление после любой возможной неисправности этим не гарантируется.

Вернуть файл патча к оригиналу, без действий с устройством:

```sh
python3 gp5_language_patch.py restore firmware_languages.bin -o firmware_restored.bin
```

Патчер проверяет, что восстановленный файл побайтно соответствует SHA-256 официального оригинала.

## Изменение прошивки

В блоке b с началом в контейнере `0xa43dc`, смещение `0x53a8` (файл `0xa9784`):

```text
04 00 00 57    LWI  r0,[r0+348]
44 00 00 03    MOVI r0,#3
```

Следующая инструкция остаётся `RET5 r30`. Патч заменяет прочитанную маску доступных языков константой 3. Инструкция декодирована инструментом на базе декодера NDS32 из OpenOCD.

Цепочка инициализации:

1. `b:0x35770` вызывает `b:0x538c`, возвращающую размер конфигурации 352.
2. `b:0x35778` загружает адрес `0x1e0000`.
3. `b:0x3577c` вызывает `b:0x5394`, проверяющую размер/маркер `0x5aff` и читающую u32 по смещению 348.
4. `b:0x35780` передаёт результат в `b:0x4dec`, строящую список разрешённых языков по установленным битам маски.
5. `b:0x4e98` выбирает язык по индексу в этом списке. Таблицы строк содержат английский и китайский.

При сканировании статических прямых JAL найден один вызов `b:0x5394`, из `b:0x3577c`. Косвенные вызовы этим сканированием не исключены.

Предположение патча: маска 3 откроет ID 0 и 1. Функция построения списка поддерживает эту интерпретацию. Открытие английского на педали и результат подключения iOS Suite подтверждены пользователем. Доступность обоих пунктов меню и точные байты протокольного ответа отдельно не зафиксированы. Патч не меняет заводские данные, идентификатор устройства, таблицы переводов и команды обновления. Поскольку это подмена чтения при запуске, повторная официальная прошивка уберёт её.

## Что означает Unlocked successfully

Исследовано официальное Android-приложение Valeton Suite 1.1.2:

- URL: https://res.valeton.net/update/gp-5/pkg/Valeton_Suite_1.1.2.apk
- SHA-256 APK: `8f4512ac6a2773acb972c1a685ff2c67790cbda61359ea224b18f162962eb1c4`.
- Dart AOT ARM64, Dart 3.5.0. Адреса ниже относятся к `libapp.so`.

`_GlobalSettingPageState._handleTap` (`0x62a420`) проверяет непустой идентификатор устройства и открывает `SetLanguageDialog` после трёх нажатий за интервал менее 1500 мс. Точное соответствие области нажатия конкретному видимому элементу интерфейса здесь не подтверждено. Код находится в глобальных настройках; обработчик GestureDetector оборачивает изображение устройства.

Обработчик подтверждения `SetLanguageState` (`0x731c58`):

1. Проверяет, что поле кода непустое.
2. Вызывает `InformationEncryptionUtil.decryptData(код, идентификатор)`.
3. Отклоняет результат `fail` и дополнительное недопустимое значение.
4. Соединяет идентификатор с возвращённой строкой маски.
5. Вызывает `generateEncryptedData(эта строка, идентификатор)`.
6. Вызывает `PresetModel.sendLanguage`, передающий полученные байты в `HtDevice.addSendData` с командой `0x33`.
7. Сразу показывает `Unlocked successfully.`

Между постановкой команды в очередь и сообщением отсутствует ожидание ответа устройства. Сообщение подтверждает прохождение клиентского пути, а не успешную запись на педали. Наличие соответствующего обработчика команды 0x33 именно у GP-5 1.0.6 ещё не доказано; приложение поддерживает несколько моделей.

`decryptData` (`0x732618`) при непустом идентификаторе разбирает JSON, проверяет два значения времени и допустимый период, затем читает `languages` и вызывает `getLanguage`. При пустом идентификаторе возвращает первые 32 символа расшифрованной строки: этот путь используется для получения идентификатора устройства.

`getLanguage` (`0x732ae8`) возвращает `0003`, `0002`, `0001` или `0000` в зависимости от наличия двух строковых обозначений языка. Сами две короткие константы текущий экспортёр не восстановил надёжно. Названия временных полей также нельзя выдавать за установленные. Поэтому генератор гарантированно рабочего активационного кода пока не подготовлен.

Восстановленная упаковка `CustomCipher`:

- первый байт: длина ключа;
- затем байты самого ключа;
- затем преобразованные байты полезной строки;
- внешнее представление: hex;
- шифрование байта: `ROR8(plain[i] XOR key[i % key_length], 2)`;
- расшифрование: `ROL8(cipher[i], 2) XOR key[i % key_length]`;
- при непустом ожидаемом идентификаторе извлечённый ключ проверяется на совпадение.

Функции: `CustomCipher.encrypt 0x732178`, `_processData 0x7322d0`, `decrypt 0x732fd4`. Клиентский путь использует эту самописную схему; это не доказательство отсутствия дополнительных проверок на стороне педали.

## Автоматический язык приложения

`GlobalModel.updateGlobalLanguage` (`0x6852f0`) сохраняет полученный язык устройства. При непустом идентификаторе значение 1 задаёт `zh`, остальные значения задают `en`. При пустом идентификаторе приложение сохраняет текущий собственный язык.

`PresetModel.updateDeviceUUId` (`0x73361c`) расшифровывает ответ идентификатора, сохраняет строку и повторно вызывает `updateGlobalLanguage` с ранее полученным языком устройства. Это объясняет смену языка при подключении.

Подмена идентификатора пустым могла бы затронуть другие функции. В этом патче она не используется. Ожидаемый путь: открыть оба языка, выбрать English на педали и проверить, что приложение получает язык 0 и переключается на английский. Патч не запрещает приложению синхронизировать язык с педалью. Идентичность iOS-кода не установлена, но пользователь подтвердил, что iOS Suite после патча и выбора английского тоже работает на английском.

## Проверки выполнены локально

- CRC всех пяти блоков оригинала совпадают с восстановленным алгоритмом.
- CRC всех пяти блоков и всего патченного файла совпадают; обновлённый `gp5_diag.py check` возвращает `valid: true`.
- Обратная замена и пересчёт CRC восстанавливают оригинал побайтно.
- Изменения ограничены инструкцией, CRC блока b и CRC контейнера: изменилось 6 байтов.
- Повреждение блока отклоняется диагностическим скриптом даже при корректно пересчитанном внешнем CRC.
- Иная модификация с корректными CRC отклоняется патчером по SHA-256.
- Существующий выходной файл не перезаписывается.
- Оба скрипта проходят Python-компиляцию; новая инструкция декодируется как MOVI r0,#3.
- В этой среде нативные вызовы недоступны. Пользователь выполнил `native-crc` на Mac: `checkCrc return_code 0`, затем успешно записал образ и подтвердил английский на педали и в iOS Suite.
